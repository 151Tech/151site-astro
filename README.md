# 151 Coffee

The 151 Coffee marketing site. Astro (static output), content from Storyblok,
deployed on Webflow Cloud.

## Running it locally

```sh
npm install
npm run dev
```

The dev server runs at `localhost:4321` and reads *draft* content straight
from the Storyblok API, so unpublished edits show up immediately.

| Command | What it does |
| :------ | :----------- |
| `npm install` | Install dependencies |
| `npm run dev` | Start the local dev server |
| `npm run build` | Build the production site to `./dist/` |
| `npm run preview` | Serve the built site locally |
| `npm run storyblok:snapshot` | Regenerate `src/data/storyblok-snapshot.json` |
| `npm run check` | Lint, type check and test - the same gate CI runs |

## How content works

Production does not call Storyblok at request time. Webflow Cloud's network
path to the API is unreliable enough that builds read from a committed
snapshot instead: `src/data/storyblok-snapshot.json`, regenerated by
`.github/workflows/storyblok-rebuild.yml` whenever an editor publishes.

That means a hand edit to the snapshot file is temporary. It will be
overwritten by the next rebuild, so content fixes belong in Storyblok.

## Checks

```sh
npm run check     # lint + types + tests, same as CI
```

Or individually:

| Command | What it does |
| :------ | :----------- |
| `npm run lint` | ESLint over `src/`, `public/js/`, `storyblok/` and the tests |
| `npm run lint:fix` | The same, applying the fixes it can |
| `npm run typecheck` | `astro check` - types across `.astro`, `.ts` and bundled scripts |
| `npm test` | Vitest, once |
| `npm run test:watch` | Vitest, watching |
| `npm run format` | Prettier, writing |
| `npm run format:check` | Prettier, reporting only |

`.github/workflows/ci.yml` runs lint, types and tests on every push and pull
request.

**There is no build check, here or in CI.** Webflow Cloud injects the
Cloudflare adapter at deploy time and runs `astro build` itself. This repo
configures no adapter, so `npm run build` fails locally with
`NoAdapterInstalled`. That is expected, not a broken setup. It does mean
build-time and runtime breakage only surfaces on a real deploy, which is why
the checks below lean on unit tests for the logic that can be tested off the
platform.

**Prettier is not part of `npm run check`.** Its config is here and the
commands work, but the existing code was never formatted with it and
`npm run format` would rewrite ~86 files in one go, including the
deliberately compact inline CSS in the `.astro` pages. Formatting the repo is
a decision worth taking on its own, not a side effect of a lint run.

### What the tests cover

Vitest runs against plain modules only - no component rendering, since the
pages need the Storyblok data and the platform adapter to mean anything.

- `tests/menu-urls.test.mjs` - every public menu URL comes from
  `src/lib/menu-urls.mjs`, so the pinned category segments are asserted
  literally. Also walks the real snapshot to prove no two products collide on
  one URL.
- `tests/store-data.test.ts` - the hand-maintained files under `src/data/`
  (landmarks, amenities, cross streets) are keyed by store slug, and nothing
  at build time checks them against the store list from Storyblok. These
  tests do: a store added in the CMS, or a slug typo'd in a JSON file, fails
  here instead of silently rendering an incomplete page.
- `tests/seo.test.ts` - meta description trimming, JSON-LD `prune`, and the
  free-text opening-hours parser, which is deliberately conservative because
  wrong hours in structured data are worse than none.
- `tests/html.test.ts` - escaping, and `faqAnswerHtml`, the one place CMS
  text becomes raw HTML.

### Lint policy

Modern rules (`no-var`, `prefer-const`) apply to module code under `src/lib/`,
`src/pages/api/`, `storyblok/` and `tests/`. They are off for the inline
`<script>` blocks in `.astro` pages and the classic scripts in `public/js/`,
which are older-style browser code and in places embed vendor snippets that
have to stay byte-identical. Correctness rules - undefined variables, unused
bindings, `eqeqeq` - apply everywhere.

`no-undef` matters most in `is:inline` scripts: `astro check` does not type
check them and they are not bundled, so ESLint is the only thing catching a
typo'd identifier before it becomes a `ReferenceError` in someone's browser.

## Layout

```text
public/          static assets, plain CSS and JS served as-is
src/components/  shared components; blocks/ holds the Storyblok block types
src/layouts/     page shell
src/lib/         Storyblok client, SEO helpers, integrations
src/pages/       routes
storyblok/       schema and content scripts run against the space by hand
webhook-relay/   Cloudflare Worker that relays publish webhooks to GitHub
```

Notes worth reading before changing something: the comments at the top of
`src/lib/storyblok.ts` (why it is a plain fetch, and how draft mode works)
and `public/js/maplibre-map-helpers.js` (why the maps are not Leaflet).
